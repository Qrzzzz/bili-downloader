## 证据位置与重现

原始证据位于忽略目录 `build/validation/`：`pytest-final.log`、`transport-final.log`、`build-winui.log`、`native-verified/native-evidence.json`、`package-final/native-evidence.json`、`package-smoke.log` 和 `artifact-audit.json`；原生截图与各自 JSON 位于同一目录。测试所用配置和运行日志均隔离在各次验证目录，不读取真实用户登录态。

可直接运行 `dist/BiliDownloader.v2.6.win-x64/BiliDownloader.v2.6.exe`，保留整个目录。完整 ZIP 为 `dist/BiliDownloader.v2.6.win-x64.zip`，SHA-256：`e8cc00662ed18e0c73a9870ba25732ec3969e372af22e1144fac680a9a00cd72`。本地候选包已按最终前端增量更新并重新归档审计，不是正式 Release。

在配置好源码后端环境后，运行编译出的 `BiliDownloader.v2.6.exe --self-test --ui-regression`，并设置 `BILI_ACCEPTANCE_OUTPUT` 到一个空的绝对输出目录，即可重跑截图和状态检查。`--ui-regression` 还要求 `BILI_BACKEND_SOURCE/tests/fixtures/winui_peer.py` 存在；仅 `--self-test` 使用真实配套后端，不需要该测试夹具。

`--self-test` 会写入测试设置草稿、占位结果文件并安全退出，必须使用隔离的 `APPDATA` 和 `LOCALAPPDATA`。成品可用现有 `tools/package_smoke.ps1` 完成隔离。

## 证据边界

- `native-evidence.json` 中每张截图标注 `fixture`；视频、进度和结果使用确定性样例，空的示例媒体文件只用于文件操作可用性检查，不是下载成品。
- 真实后端启动、无效输入校验、主题、原生窗口、导航和设置读取已实测。本轮未运行真实手机扫码、成功 MP4/MP3 下载或平台限制探测。
- 175% 的实机截图不能替代其他 DPI、跨屏移动、高对比度或读屏的完整人工验收。相关手工检查仍需维护者确认。
- 上述本地构建保留 `dirty=true`，不得替代正式 Release。清理盘点及被系统阻止的 8 个旧日志见 [审查记录](../architecture/v2.6-winui-review.md)。
- 清理旧候选目录的显式删除命令也被系统策略拒绝，因此保留本轮早期截图目录和安装器下载文件；最终有效证据以 `native-verified` 与 `package-final` 为准。

## 发布流程与远端证据

2026-09-04 用户明确要求“进入release流程”，授权提交、PR、CI、合并、标签及 GitHub Release。该授权不等同于补齐上方尚未完成的人工验证。
