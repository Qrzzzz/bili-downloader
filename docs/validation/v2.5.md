## 正式发行证据

本地构建带 `dirty=true`，仅用于开发验收，不上传为正式 Release。正式资产必须由合并后的精确 `v2.5` 标签提交生成，`build.ps1 -RequireClean -ExpectedCommit ... -ExpectedTag v2.5` 绑定版本与提交。

发布顺序为 PR Quality → 合并内容核对 → main Quality → annotated tag → Release 干净构建 → package smoke 与 ZIP 审计 → 联合 SBOM/摘要 → 三个资产的来源证明及验证 → GitHub Release → API 核对标签、提交、资产和 digest。

远端结果以该标签对应的 [Actions](https://github.com/Qrzzzz/bili-downloader/actions) 和 [Release](https://github.com/Qrzzzz/bili-downloader/releases/tag/v2.5) 为准；本地候选日志不能替代远端构建证据。
