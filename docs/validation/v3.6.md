# 3.6 本地候选验证

日期：2026-10-04。基线：3.5 / main `14f288c`。分支：`codex/v3.6-batch-media`。
本轮只实现 [#39](https://github.com/Qrzzzz/bili-downloader/issues/39) 批量逐项草稿与 [#41](https://github.com/Qrzzzz/bili-downloader/issues/41) 长媒体处理评估。本地验证完成后，用户授权推送、发布，按 PR、CI、合并、注释标签与 Release 工作流推进。

## 行为与兼容

- 每项保存 MP4/MP3、偏好高度、目录和分 P；切换项目自动恢复。摘要区分共用默认值、单项覆盖及入队冻结。明确应用默认值只更新未覆盖项，单项重置恢复默认与链接分 P。
- 批量入队前复制每项规格；严格画质缺失、空选择、无效目录和后端入队错误按项提示。成功项冻结；失败项保留草稿及同规格提交 token，重试不再次创建成功项。
- 设置同步不覆盖正在编辑的草稿；切页保留，重新解析、更换输入/账号模式或退出清除。单项添加、偏好记忆、任务数据库、登录与 IPC v2 继续兼容。
- 完整解码预算采用 `min(1800, max(300, 30 + duration_seconds × 0.5 + size_bytes / 16 MiB))`。有效时长来自所选 FFprobe，缺失时回退所选 FFmpeg 的元数据；非有限、非正或未知时长维持 300 秒。元数据仍独立限制为 10 秒。保留全音视频解码、严格高度、MP3 192 kbps 和输出前后文件大小/修改时间检查。
- 合并/转码结束后归还处理槽，再排队校验。新版本实例按票据序号 FIFO 进入同一个跨进程媒体槽；每张票据另持 OS 活动锁，进程终止后由后续请求回收。等待取消不影响槽拥有者；票据及临时锁清理。与旧版本共用原处理锁保持互斥，旧进程不参与 FIFO 顺序保证。
- 合并中已延迟的取消使用独立验证控制器重新取得媒体槽，完整校验仍有上限；通过才保留当前成功文件，后续分 P 取消。普通验证和复用验证继续可取消。

## 先测量再决定

工具：`tools/measure_media_verification.py`。Windows、Python 3.13.14、FFmpeg 8.0；先以原生产校验运行，之后再实施预算与排队变更。合成 H.264/AAC 样本由 2 秒测试图/音频循环扩展，测试图不是复杂真实长片。另验证已有真实 Bilibili 下载的 212.31 秒 360p 文件；没有重新下载媒体。

| 样本 | 文件 MiB | 原预算完整解码秒 | 原预算 CPU 秒 | 3.6 完整解码秒 |
| --- | ---: | ---: | ---: | ---: |
| 合成 1 小时 360p / 30 fps | 177.11 | 5.207 | 44.109 | 5.249 |
| 合成 10 分钟 1080p / 30 fps | 161.70 | 3.817 | 49.828 | 3.924 |
| 合成 5 分钟 2160p / 30 fps | 293.91 | 8.399 | 110.719 | 8.271 |
| 合成 1 小时 MP3 / 192 kbps | 82.40 | 1.594 | 3.297 | 1.635 |
| 缓存真实下载 360p / 212.31 秒 | 9.17 | 2.766 | 7.156 | 2.751 |

以上全部通过完整解码，本机未复现原 300 秒误拒。CPU 秒为 FFprobe 与 FFmpeg 的进程 CPU 时间之和，多核下可大于墙钟时间。记录同时保存进程读取字节计数，例如 4K 解码约读取 309 MB；操作系统缓存会影响结果，进程读取量不是物理磁盘吞吐测量。

两个解码线程的原 4K 耗时为 40.729 秒、解码 CPU 为 77.734 秒；默认线程为 8.399 秒、110.688 CPU 秒。两线程节省 CPU 总工作时间，但增加等待约 4.8 倍，因此保留默认线程和单槽并发上限。实测最慢比率约 0.136 秒/媒体秒；时长系数 0.5 为该样本保留约 3.7 倍余量，并增加保守的 16 MiB/s 读取预算。系数不是全部硬件/编码的性能承诺，上限避免无界等待。

真实并发三个独立进程在隔离 profile 中对 4K、MP3、1080p 使用生产媒体槽与完整解码：等待约 0.002、8.134、9.016 秒，解码约 8.529、1.635、3.700 秒，全部通过。另一组独立进程验证合并释放后的校验排在已有两项之后，取消及强制终止等待者不会阻塞后续项。此类排队测试是真实 OS 锁/子进程证据，媒体阶段动作夹具与真实解码测量分别记录。

证据：`build/v36-media-baseline/measurements.json`、`build/v36-media-final/measurements.json`；最终汇总保存在 [v3.6-media.json](./v3.6-media.json)。合成样本和缓存文件属于本地测试产物。
