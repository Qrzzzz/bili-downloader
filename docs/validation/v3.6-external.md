## 环境与证书

Windows、Python 3.13.14、OpenSSL 3.5.7、certifi 2026.07.22、受控 FFmpeg 8.0。对 `api.bilibili.com` 的 certifi 与系统信任校验均通过；真实媒体任务保持 TLS 校验，没有绕过平台拒绝。未复现 3.0 的证书错误，历史错误根因仍不能据此确定。

每组任务使用独立 APPDATA / LOCALAPPDATA / USERPROFILE 和生产 TaskManager、SQLite、暂存与媒体锁。匿名任务不读取本机登录态。媒体、数据库、原始日志仅在被 Git 忽略的 `build/` 下保存；公开 JSON 只列视频编号、随机任务/轮次编号、终态、文件名、字节数、SHA-256、媒体元数据和检查退出码，不导出本机路径或凭据。

用户提供的视频在匿名模式只展示“最佳可用画质”，多分 P MP4 因此冻结为该规格，不伪称通过严格 360p 选择。每个结果均核对已选分 P、逐 P 终态、saved_files 的集合一致性、MP4 音视频/容器或 MP3 192 kbps 规格，并对真实文件执行独立完整解码。文件 SHA-256 用于本轮输出追踪，不是发布包校验和。

多分 P 另在 P1 已成功发布、P2 真正收到下载字节后执行取消或终止进程，四组再次通过。继续/恢复后，已完成 P1 的文件名及 SHA-256 均保持一致，P2 完整补齐；JSON 中 `published_before_control` 与 `retained_outputs_unchanged` 记录这一检查。取消后的已完成逐 P 记录与重启后的文件复用是各自的真实生产路径，不以合成文件代替。

进程恢复验收在真实下载通知处设置测试同步屏障，再终止该隔离 Python worker，避免快速下载在控制动作前完成；没有替换网络响应、生产下载函数或媒体。这证明实际进程中断后的数据库、锁与媒体恢复，不代表已经人工点击 WinUI 关闭按钮。终止时尚未启动该分 P 的 FFmpeg；工具的整体超时会回收自己 worker 的进程树。

## 工具修复与回归

- 新增 `tools/public_task_lifecycle.py`：显式 opt-in 的单/多分 P、MP4/MP3 取消和独立进程恢复验收。每组使用新目录，最多两 P、每 P 最多 600 秒，并限制整体等待。完整解码独立限制为 300 秒，仅针对这些短验收样本，不改变生产长媒体预算。
- 修复 `tools/public_task_smoke.py` 的报告缺口：保留 `first_attempt` / `initial_outcome`，重试后重新检查真实最终文件并写入 `final`。失败重试后不再只报告一个状态标签，也不会抹掉首次失败。并行通过要求确实观察到两个活动任务。
- 新增离线报告回归，拒绝缺失分 P、取消项、元数据/解码失败、空文件、错误画质、音频码率、容器和文件集合不一致；验证首次失败与重试成功同时保留。离线回归不作为公网证据。
- Python 全量：511 passed（`build/issue42-pytest.log`）；工具最终改动的相关回归：65 passed（`build/issue42-final-related.log`）。相关回归单独运行时有一条 pytest_socket 导入探测警告，套接字被阻止，没有实际公网访问。生产 C# / WinUI 未修改，沿用 [3.6 原生与管道记录](./v3.6.md)，不将其写成本轮重新执行。
