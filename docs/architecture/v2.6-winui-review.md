## 审查发现

| 优先级 | v2.5 证据与影响 | 本轮处理 |
| --- | --- | --- |
| P1 | `DownloadPage.InputBox` 未绑定忙碌状态；下载中改链接触发 `Invalidate()`，清除解析对象并取消重试资格。 | 锁定下载、关闭期间的输入；命令入口检查当前能力，保留解析中修改输入后抑制迟到结果的语义。 |
| P2 | `ProgressVisibility` 直接取应用级 `Busy`，账号验证、二维码、诊断也在下载页显示旧的下载进度和取消按钮。 | 仅下载页所属任务展示进度；其他任务用准确的忙碌提示说明不可用原因。取消请求有等待状态，避免重复提交。 |
| P2 | 封面、标题、格式、画质、路径逐项纵排；无主按钮强调，默认窗口中常需滚动才能开始下载。 | 紧凑视频摘要、规格双列、目录同行操作；窄窗口改为单列。保持字号、系统控件和清晰留白。 |
| P2 | 结果区总显示空文件下拉框和不可用重试；长路径成为主要视觉内容；返回页面总抢焦点到输入框。 | 单文件显示文件名，多文件才显示选择器；无文件隐藏文件区；保留逐 P 详情、可用重试与打开目录。结果出现后定位结果，切页保留视图。 |
| P2 | 账号没有保存状态代码，未登录也显示清除入口；登录期间状态和隐私长文缺少层次。 | 使用真实状态代码决定登录/管理入口；二维码生成反馈、当前状态与可展开隐私说明分层。 |
| P2 | 设置页每次进入直接 `ReloadAsync`，未保存的目录/主题静默丢失；下载结束也可覆盖草稿。 | 保留未保存草稿，显式显示待保存状态，保存中防重复提交；外观选择即时预览，失败恢复已保存主题。 |
| P2 | 启动说明和高频下载进度反复写全局 InfoBar，重复页面文本，读屏状态更新过密。 | 初始帮助放在页面，InfoBar 保留重要状态与错误；局部任务阶段提供状态文本。 |

保留 Windows App SDK 2.4.0、.NET SDK 10.0.400、IPC 1、配置 schema 1、Python 3.13、匿名/本机登录态、MP4/MP3、分 P、DPAPI、取消/关闭与失败重试协议。不会因平台拒绝而修改网络或权限边界。

布局使用默认 WinUI 资源及视图宽度下的重排；全局通知遵循 [Microsoft InfoBar 指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/infobar)，布局依据 [Microsoft XAML 响应式布局说明](https://learn.microsoft.com/en-us/windows/apps/develop/ui/layouts-with-xaml)。
