# v2.5：Windows App SDK / WinUI 3

应用版本为 **2.5**。Windows App SDK **2.4.0**、.NET SDK **10.0.400**、IPC **1**、配置 schema **1** 是相互独立的版本号。这里记录实际实现；外部验收状态见 [v2.5 验收记录](../validation/v2.5.md)。

## 审计结论与迁移边界

迁移前，`app/ui_main.py` 同时包含窗口构建、页面协调、不可变下载请求、QR 工作循环、解析/下载/诊断 worker、QThread/Signal 连接、迟到回调抑制和关闭等待。`app/ui_dialogs.py` 包含结果展示与打开文件/重试交互；前序 v2.4 的 `app/ui/` 提取了页面与主题，但业务生命周期仍由 Qt 主窗口持有。

`app/main.py` 负责启动 Qt、异常钩子、运行标记和解析 smoke。`app/downloader.py` 的 yt-dlp、分 P、格式策略、FFmpeg 后处理和取消逻辑可独立复用，唯一 UI 依赖经 `logger.LogEmitter` 传入。`app/auth_qr.py` 是 requests/Segno 协议实现；`app/cookies.py` 是 Cookie 校验、DPAPI、跨进程锁及临时 lease；二者无需重写。`app/config.py` 的目录和主题偏好继续使用 schema 1。

| 层 | v2.5 归属 | 处理 |
| --- | --- | --- |
| 窗口、页面、焦点、主题、对话框 | `BiliDownloader.WinUI/` | C# + WinUI XAML |
| 应用级显示状态 | `Services/ApplicationSession.cs` 与 `ViewModels/` | 跨 Page 持续存在，不在切页时创建任务 |
| IPC、任务串行化、版本/代次、快照、取消 | `app/backend/` | 普通 Python 线程、Event、队列，无 Qt |
| QR 工作循环、下载请求及服务适配 | `app/services/` | 从原 UI glue 提取，保留事务顺序 |
| 下载、URL、QR 协议、Cookie、DPAPI、FFmpeg、诊断 | 既有 `app/*.py` | 原实现保留；downloader 的日志参数改为 callback |
| 日志通知 | `app/logger.py` | `Callable[[str], None]`，保留轮转、分类与脱敏 |

原始 Qt 源码已从 v2.5 运行路径和源码树退役。旧版本的发布记录与 `docs/releases/v2.4.md` 作为历史保留。开始迁移前的未提交 v2.4 工作另有本机备份，未用 Git reset 覆盖。

## 官方 API 与窗口生命周期

`MainWindow : Microsoft.UI.Xaml.Window` 只负责 shell：`Window.SystemBackdrop` 设置 `MicaBackdrop`；真实 `TitleBar` 交给 `SetTitleBar`，并开启 `ExtendsContentIntoTitleBar`。没有自制最小化、最大化或关闭 Button。系统 caption 主题使用 `AppWindow.TitleBar.PreferredTheme`；最小尺寸使用 `OverlappedPresenter.PreferredMinimumWidth/Height`，按当前 DPI 转换。

`NavigationView` 自动适应宽度，内含 `Frame`，三个 Page 各自缓存视图。状态用 `InfoBar`；登录保存同意与清除确认使用 `ContentDialog`，传入当前 `XamlRoot` 和主题。目录选择与打开文件使用 Windows picker/Launcher API。下载开始及展示结果时收起规格区，结果仍在下载页内。

默认 Control Style、Typography 和 ThemeResource 承担外观；卡片背景为 `CardBackgroundFillColorDefaultBrush`。根元素 RequestedTheme 跟随保存偏好，system 模式监听 Windows UISettings。高对比度依赖 WinUI 的系统资源机制，不能用普通深色截图代替高对比度验收。Manifest 声明 PerMonitorV2；不固定像素缩放或手绘窗口边框。

系统关闭首先在 `AppWindow.Closing` 中取消本次关闭，然后请求后台停止，等请求会话、Cookie lease、下载/后处理和输出管道释放后关闭窗口。程序主动关闭也走同一协调器，因为系统 Closing 事件不覆盖 `AppWindow.Destroy`。不强杀正在运行的 FFmpeg。

## 进程与分发

WinUI 从自身目录启动 `BiliDownloader.Backend.exe`，不搜索 PATH。源码调试只接受显式绝对路径 `BILI_BACKEND_PYTHON` 和 `BILI_BACKEND_SOURCE`。UI 为 WinExe，后端保留标准管道，并由 `CreateNoWindow` 隐藏控制台。

发布为 self-contained、unpackaged x64 目录 ZIP：UI EXE、后端 EXE、WinUI/.NET 库位于根目录，Python 库位于 `backend-runtime/`。EXE 相邻 `tools/ffmpeg.exe` 的既有语义保持不变。发行包包含 SDK 的 WebView2 projection/loader 等传递依赖，但没有 WebView 控件、网页 UI、Chromium/Edge 运行时或浏览器进程。未经实际验证不裁剪 Microsoft SDK 自身的依赖。

Python 使用哈希锁，NuGet 使用 locked restore。前后端共享 build-info，并在 PE/程序集元数据中绑定 commit/dirty。审计同时检查 ZIP 路径、目录成员及后端内嵌 PYZ。联合 CycloneDX 清单区分锁定构建依赖和实际交付文件摘要；`licenses/` 包含恢复包中的许可证、notice 和 nuspec。

保留官方模板的 `EnableMsixTooling=true`，让 SDK 的 PRI/XAML 发布目标生效；`WindowsPackageType=None` 继续决定采用非 MSIX 的目录分发。应用 XBF（包括所有 Page）由官方工具嵌入 `BiliDownloader.v2.5.pri`。发布审计要求该资源索引存在，最终包原生启动检查负责验证资源实际可加载，不能只以 `dotnet publish` 成功作为可运行证据。

## 分阶段落地与保留文件

1. 审计与架构确认：识别 UI、业务与线程 glue；先保全既有工作树。
2. Backend adapter：日志 callback、服务、IPC v1、取消和重试快照，复用全部业务回归。
3. Native shell：真实 WinUI 项目、窗口、主题、导航、页面和应用级显示状态。
4. 功能接线：解析、元数据、封面、分 P、MP4/MP3、结果、重试、账号与诊断。
5. 验证和退役：管道故障测试、原生窗口检查、包审计；删除 Qt UI 和仅适用于 Qt 的测试，生命周期场景迁入服务测试。
6. 外部验收与发布：真实手机登录、平台允许的下载、DPI/高对比度/读屏和窗口行为；获得发布授权后才执行远端发布。

保留且业务不改：`auth_qr.py`、`cookies.py`、`video_urls.py`、`utils.py`、`diagnostics.py`、`crash.py`、资源图标、安全与使用声明。保留并适配：`main.py`、`downloader.py`、`logger.py`、版本、依赖锁、构建与发布脚本、测试和说明。删除：`ui_main.py`、`ui_dialogs.py`、`app/ui/`、旧 `BiliDownloader.spec`、Qt 专属界面测试。`config.py` 延续前序 theme 字段，不改 schema。
